4. MATHEMATICAL AND COMPUTATIONAL CORRECTNESS RULES
======================================================================

4.1 MODULAR ARITHMETIC / COPRIME TRAVERSAL

For N = 97,152:
  N = 2^7 * 3 * 11 * 23
  phi(N) = 28,160

Let U be a deterministic ordered list of residues u in [0,N) such that
  gcd(u,N) = 1.

For start index a and stride s where gcd(s, 28,160)=1:
  F(k) = U[(a + k*s) mod 28,160]
  R(k) = U[(a - k*s) mod 28,160]

These are opposing traversals of the same finite index set. Verify coverage,
uniqueness and closure exhaustively for test-sized domains. Define canonical
ordering of U; otherwise the mapping is underspecified. Do not call phi(N)
an inverse. Do not treat a prime factor such as 23 as a positional marker
unless the routing mapping explicitly assigns it that meaning.

Checkpoint percentages (11%, 22%, 33%, ... 99%) are sampling/observation
markers. They may reduce redundant work only when mathematically safe; they
must never bypass required integrity checks or hide skipped intervals.
Record skipped ranges and prove coverage.

4.2 MODULAR INVERSE

For a modulo m, inverse a^-1 exists iff gcd(a,m)=1. For e=65,537:
  d = e^-1 mod m
is only defined after the exact modulus m is known and gcd(e,m)=1.
For RSA-style use, m is usually lambda(n)=lcm(p-1,q-1), not an arbitrary
assumed modulus. Do not invent missing factors or a modulus.

4.3 REVERSIBLE TRANSFORMATIONS VS HASHES

A reversible transform can be inverted only if its mathematical domain,
range and parameters permit it. A cryptographic hash such as SHA-256 or
BLAKE2b is intentionally one-way; a digest alone does not reveal a unique
previous or next digest. A hash chain can be traversed only when the linked
preimage/record or external structure is available. A quotient/residue
projection or coprime index map does not invert SHA-256.

Use:
- ARX or another reversible permutation for reversible diagnostic replay;
- SHA-256/BLAKE2b for content fingerprints/integrity digests;
- signatures/MACs with managed keys for authenticity;
- Merkle proofs/append-only records for inclusion and history integrity.
Never label an arithmetic checksum as a cryptographic hash or a plain hash
as proof of author identity.

4.4 AE.MINERVA.UNBOUND.INVERSE

Given target Y, inverse G and forward F:
  X = G(Y)
  Y_check = F(X)
  accept right-inverse iff Y_check == Y.
For a full bijection claim, also test G(F(X)) == X over the declared domain.
The verifier must receive compatible parameters/domain/codomain, preserve
input immutability, return structured ACCEPTED / REJECTED / UNRESOLVED,
and issue evidence only after comparison. If an inverse is not defined,
return UNRESOLVED; do not fabricate reconstruction.

4.5 FOUR-LANE ENGINE

Pair A: L1 automation 1234; L2 shadow 4321.
Pair B: L3 automation 4321; L4 shadow 1234.
Each lane has its own cursor, source ticket, opposing ticket, sequence ID,
polarity, operator-set version, fractional cursor and whole-cycle count.
The source ticket is immutable. Shadow parameter tuning is versioned and
cannot rewrite the source. Pair residuals and cross-pair closure are
separately measured. A reverse ordering is not itself an inverse.

Preserve signed direction/polarity; never erase signs using absolute value
where orientation matters. Keep fractional and whole-cycle delimiters
separate. The visualization renders kernel state; it does not decide truth.

4.6 ERROR CORRECTION

Integrate QC-LDPC (quasi-cyclic LDPC) as the selected LDPC family, plus
recursive Reed-Solomon over GF(256) where appropriate. Define code profiles,
block sizes, parity checks, syndrome calculations, decoding limits,
correction counts, erasure/error semantics, and post-decode verification.
A corrected block is not accepted until the independent integrity/semantic
verification stage passes. Record original, corrected and residual data.
Do not silently change the selected QC-LDPC approach to a random sparse
matrix.

- nominal base interval T = 100,000 ns = 100 microseconds = 0.1 ms;
- solver/convergence window S = 500,000 ns = 5T = 0.5 ms;
- monotonic one-second epoch E = 1,000,000,000 ns;
- nominally 10,000 base intervals and 2,000 solver windows per second;
- external UTC/precision-time correlation, independent lane accounting,
  adaptive work admission and timestamped receipts.

kernel use process.hrtime.bigint() for monotonic elapsed-time measurement.

JavaScript, a browser, Node.js, or a general-purpose OS will execute every

behavior without a real-time OS/hardware test environment.

Adaptive controller responsibilities:
- measure actual throughput and latency;
- estimate safe work budget;
- adjust batch admission within explicit bounds;
- publish recommendation and confidence/provenance;
- never redefine correctness thresholds to make a failed run pass.

Sequential trigger pipeline:

PIPETHRUUC operators:
  |    pipe
  >    output redirection
  <    input redirection
  <--  reverse redirection
Tokenize <-- before < and >. Preserve original source, byte/character
positions, Unicode normalization choice, operand identity, precedence,
signedness, locale and parse diagnostics. Never silently translate a
command into a semantically different command.

AXIR should represent typed operations, values, references, effects,
capabilities, permissions, execution context, dependencies, error policy,
and provenance. Separate parsing from execution. Require an explicit
permission/capability check before side effects. Provide dry-run/plan mode
for review; execution mode must show the exact native command/backend and
require confirmation for high-impact actions.

Shebang-free behavior:
- text source needs an explicit interpreter or launcher dispatch;
- examples: python axs.py, py axs.py, node axs.mjs, bun axs.ts,
  pwsh -File axs.ps1;
- compiled native executables can be invoked directly;
- do not promise that arbitrary text files are directly executable without
  an interpreter selection mechanism.

Quine behavior:

- distinguish self-description, source regeneration, and a multi-language
