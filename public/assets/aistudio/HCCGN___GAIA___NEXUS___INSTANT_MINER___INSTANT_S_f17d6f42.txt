# 2. THREE-TIER MINING ARCHITECTURE

## TIER 1 — INSTANT MINER / INSTANT SOLVER

Designation:

`CRYPTIC.T1.INSTANT`

Purpose:

A user submits a supported computational job and immediately receives a measurable execution session.

Required capabilities:

- Select an explicitly supported algorithm.
- Select a supported network or standalone benchmark.
- Load validated job parameters.
- Initialize a computation session.
- Generate candidate inputs.
- Execute the actual algorithm.
- Evaluate candidates against the actual target.
- Submit candidates when the configured protocol supports submission.
- Independently verify results.
- Record execution time and operation count.
- Display live graphs.
- Produce a cryptographic execution receipt.

### Instant solver

The solver must remain algorithm-independent wherever the mathematics permits.

Its interface accepts:

- Input state.
- Forward operator.
- Inverse operator, when one exists.
- Algorithm parameters.
- Verification policy.
- Execution budget.

For reversible transformations, verify:

\[
F(F^{-1}(Y))=Y
\]

Where applicable, also verify:

\[
F^{-1}(F(X))=X
\]

Do not claim that SHA-256 or BLAKE2b can be inverted merely because an inverse-indexing or reversible arithmetic transformation exists.

Cryptographic hashes remain one-way functions for the purposes of this system.

The solver must distinguish:

- Exact inverse reconstruction.
- Candidate search.
- Error correction.
- Statistical estimation.
- Cryptographic digest verification.
- Consensus target validation.

These are different computational operations.

### Instant execution interface

Provide:

- Start.
- Pause.
- Resume.
- Stop.
- Cancel.
- Reset.
- Verify.
- Export receipt.

Display actual measured:

- Completed operations.
- Candidate count.
- Valid candidates.
- Hash calls.
- Bytes processed.
- Elapsed time.
- Operations per second.
- Hashes per second.
- Average latency.
- p95 latency.
- Verification status.
- Current execution state.

No hardcoded performance claims.

# 3. HCCGN UNIVERSAL CLOCK INTEGRATION

Integrate the existing HCCGN.UCLK.DUAL.ADAPTIVE specification as the common temporal contract.

The clock must be independent of the visualizer and computation workers.

## Canonical timing

| Parameter | Value |
|---|---:|
| Base timing target | 100,000 ns |
| Base interval | 100 μs |
| Solver window | 500,000 ns |
| Base intervals per solver window | 5 |
| Nominal intervals per second | 10,000 |
| Nominal solver windows per second | 2,000 |

Use integer nanoseconds internally.

Use an actual monotonic native clock for scheduling and elapsed-time measurement.

Use UTC correlation for event provenance and cross-device reconstruction.

### Dual-interval adaptive convention

Use BOTH:

- 100,000 ns nominal scheduling interval.
- Adaptive, measured computation batch.

The batch size must be determined from actual throughput and remaining execution budget.

Do not assume that 100,000 ns guarantees that the operating system can dispatch or finish a computation.

### Absolute deadlines

\[
d_n=M_0+nT
\]

Where:

- M₀ is the monotonic epoch origin.
- T is 100,000 ns.
- n is the interval index.

Measure actual dispatch:

\[
j_n=t_n-d_n
\]

Measure execution:

\[
e_n=t_{\mathrm{finish},n}-t_n
\]

Do not accumulate timing drift by scheduling each next interval relative to the previous actual wake-up.

Missed deadlines must be recorded.

No uncontrolled catch-up bursts.

### Solver cadence

Every five nominal intervals, aggregate the current computation window and invoke the solver.

The solver must evaluate:

- Four-lane execution results.
- Forward/reverse reconstruction.
- Residuals.
- Sequence continuity.
- Clock jitter.
- Computation duration.
- Verification status.

A late solver must be identified as late.

A failed solver must not be reported as converged.

### Epoch closure

Each nominal one-second epoch must record:

- Start time.
- End deadline.
- Actual elapsed time.
- Completed operations.
- Completed bytes.
- Completed hash calls.
- Valid candidates.
- Verified results.
- Incomplete jobs.
- Missed intervals.
- Solver outcomes.
- Final receipt.

Actual elapsed time must be measured. Do not assume an epoch lasted exactly one second because its nominal deadline was one second.

- REVERSED

- Receipt ID.
- Job ID.
- Worker ID.
- Epoch ID.
- Algorithm identifier.
- Algorithm version.
- Input digest.
- Output digest.
- Target.
- Candidate result.

- Verification outcome.
- Protocol submission response.

- Reward accounting reference.
- Settlement state.

Use canonical serialization.
